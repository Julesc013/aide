# AIDE Generated Outputs Policy

This document defines AIDE's permissive generated-output boundary. It is not
legal advice. The Apache License, Version 2.0 text in `LICENSE.md` controls the
AIDE material distributed under that license.

## Purpose

AIDE is designed to operate inside other repositories. It may generate or
update:

- `.aide/knowledge/okf/` pages
- `AGENTS.md` or other agent guidance
- WorkUnits
- WorkerRuns
- TestJobs
- EvidencePackets
- EventRecords
- ContextPacks
- reports
- patch proposals
- documentation drafts
- protocol projections
- adapter scaffolds
- repo-local summaries

This policy explains how those outputs should be treated under AIDE's
Apache-2.0 license.

## Short Rule

```text
Your repository content remains yours.
AIDE's own source remains Apache-2.0.
Generated outputs derived from your repository belong to you, subject to copied
AIDE material and any third-party material they contain.
```

## Definitions

**AIDE Material** means AIDE source code, documentation, templates, schemas,
prompts, examples, protocol definitions, report templates, OKF templates, and
other materials distributed as part of AIDE.

**Target Repository** means a repository, project, directory, workspace, or
codebase that AIDE is used with.

**Project-Local Output** means an output generated by AIDE for a Target
Repository based on that Target Repository's content, configuration, prompts,
evidence, or user instructions.

**Copied AIDE Material** means any substantial portion of AIDE Material
reproduced in a Project-Local Output.

## Ownership And Licensing Of Outputs

AIDE does not claim ownership over a user's Target Repository or over
repo-local facts, metadata, analysis, summaries, documentation, or generated
artifacts produced from that Target Repository.

Project-Local Outputs may be used, modified, committed, redistributed, or
relicensed by the Target Repository owner under that repository's own terms,
except that:

1. Copied AIDE Material remains available under Apache-2.0.
2. Third-party materials remain subject to their own terms.
3. AIDE trademarks and branding are not granted for misleading or official use.
4. Outputs are provided without warranty.

## Examples

Usually project-local and controlled by the target repository owner:

- an OKF page summarizing target repository architecture
- a WorkUnit describing a task in the target repository
- a TestJob result from the target repository test suite
- an EvidencePacket summarizing target repository validation
- a ContextPack assembled from target repository files
- a patch proposal against target repository files
- generated documentation about target repository behavior

Usually still AIDE Material, licensed Apache-2.0:

- AIDE schema files copied into a repository
- AIDE protocol templates
- AIDE report templates
- AIDE helper scripts
- AIDE adapter interfaces
- AIDE example code copied verbatim
- AIDE branding assets

## No Source-Truth Promotion

This policy does not make generated downstream artifacts canonical AIDE source
truth. AIDE's own source-of-truth rules remain governed by `AGENTS.md`,
`.aide/profile.yaml`, `.aide/queue/**`, and `docs/reference/source-of-truth.md`.

Generated downstream artifacts are outputs unless a future reviewed policy
explicitly marks a specific artifact class as canonical.

## No Warranty

Generated outputs are provided as-is. AIDE does not guarantee that generated
outputs are correct, complete, safe, rights-cleared, secure, production-ready,
or suitable for any particular purpose.
