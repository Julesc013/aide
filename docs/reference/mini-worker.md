### Optional Mini worker

**Current scope:** an optional source adapter for pinned upstream
mini-SWE-agent 2.4.6 DefaultAgent, with deterministic Model/Environment fixtures.
Acquisition and 15 native lifecycle scenarios passed; no model-backed
coding outcome, general Mini CLI installation or supported provider route is claimed.

The adapter keeps the upstream loop unchanged. AIDE's existing managed job and
WindowsJobHost own admission, limits, process-tree termination, collection and
retirement. Mini produces a candidate; independent checks and existing project
review own acceptance and integration.

**Use and dependencies.** The caller supplies an enabled MiniAttempt, approved
Model/Environment implementations, an exact extracted recipe and a new attempt
directory. Launch through the admitted host in a fresh isolated interpreter.
The adapter checks source/recipe identities, finite limits, dependency bytes and
distribution identities before loading Mini. Existing attempts refuse replay.
Passive import loads no optional SDK. The reviewed fixture sets owned configuration
before Mini imports; it does not read the user's Mini .env or install packages.

The selected 14-wheel recipe contains the imports used by DefaultAgent, not
Mini's complete declared provider/CLI/benchmark installation. Original metadata,
artifact hashes, notices and selected source comparisons are in
[the WorkUnit](../../.aide/queue/AIDE-MINI-WORKER-01/ExecPlan.md).
Full artifact identity is pinned; publisher authenticity is not claimed.
Different versions, dependencies, platforms or Model/Environment implementations
require applicable evidence. No automatic acquisition or provider fallback occurs.

**Results and recovery.** The adapter writes attempt.json independently of Mini's
trajectory. Work, attempt, source and recipe identities remain separate from model
serialization. A Submitted result is candidate_submitted, with accepted always
false. Exceptions preserve a failed/interrupted receipt when the process can run
cleanup; abrupt termination can leave INCOMPLETE plus the last saved trajectory.
The supervisor retains those observations and checks actual effects before any
new attempt. A new process is allowed; repeating completed effects is not.

Model usage remains unknown unless independently collected. Mini query counts,
reported costs and loop limits do not establish actual billed usage, an in-flight
spend ceiling or whole-task efficiency. This fixture makes no real model requests.

**Boundaries.** Isolated imports and owned paths are fixture controls, not OS read
isolation. The adapter accepts trusted, separately approved components; arbitrary
component code can act outside these Python checks. The existing host enforces
its qualified process/memory/time/output limits. It does not turn outer editors
or shells into confined routes. No global install, live service, autonomous
dispatch, source merge or release effect is supplied by this module.

**Qualified fixture.** Fifteen fresh-process scenarios at e2902c21 cover disabled/changed/
missing/wrong-version inputs, preloaded dependencies, finite limits, duplicate
attempts, an independently checked file repair and patch, malformed actions,
environment failure, step exhaustion, interruption, continuation without repeated
effects, and cancellation of an owned process tree with partial evidence.
Fourteen completed unittest cases and one parent-checked cancellation passed
without failures or skips on Windows / Python 3.14.8. All original outcomes are
retained. The tests are source-only under core/execution/tests, excluded from
Lite exports and frozen archives. See the task report for exact evidence and
pending final compatibility/integration checks.
