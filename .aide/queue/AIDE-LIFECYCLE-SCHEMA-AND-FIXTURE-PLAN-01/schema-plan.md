# Lifecycle Schema Plan

## Artifact Model

| Artifact | Purpose | Required fields | Validation | Evidence | Review gate | Does not authorize |
| --- | --- | --- | --- | --- | --- | --- |
| lifecycle manifest | Describes owned/generated/managed lifecycle content and boundaries. | `schema_version`, `manifest_id`, `pack_identity`, `target_root_class`, `owned_files`, `managed_sections`, `generated_files`, `manual_preservation_rules`, `protected_paths`, `allowed_target_path_patterns`, `phase_allowlist`, `preimage_expectations`, `postimage_expectations`, `rollback_record_requirements`, `validation_commands`, `evidence_requirements`, `review_gate`, `capability_reality`. | JSON parse, schema validation, forbidden-operation boundary search. | Manifest example, validation results. | `needs_review`. | Target mutation, broad writes, unknown file deletion, release, provider/model/Gateway/network calls. |
| lifecycle operation plan | Represents an explicit lifecycle operation plan. | `schema_version`, `lifecycle_plan_id`, `phase`, `mode`, `fixture_only`, `source_manifest_ref`, `explicit_operations`, `operation_allowlist`, `explicit_paths`, `allowed_roots`, `protected_roots`, `preimage_hash_requirements`, `postimage_hash_requirements`, `rollback_record_destination`, `evidence_report_destination`, `stop_conditions`, `review_gate`, `prohibited_operation_checks`. | JSON parse, schema validation, explicit-path checks. | Plan example, planned validation. | `needs_review`. | Active repo apply, target apply, implicit scans, broad deletes. |
| lifecycle transaction bundle | Carries scoped transaction plans or compatible bundles compiled from lifecycle plans. | `bundle_id`, `lifecycle_plan_id`, `transaction_plans`, `operation_order`, `single_mutating_operation_limit`, `rollback_record_refs`, `evidence_refs`. | Validate each scoped plan and bundle boundaries. | Bundle summary in future task. | `needs_review`. | Multi-file atomic apply, rollback execution, target apply. |
| lifecycle report | Records report-only, dry-run, fixture apply, or blocked lifecycle outcomes. | `schema_version`, `report_id`, `lifecycle_plan_id`, `lifecycle_phase`, `mode`, `status`, `target_class`, `target_files_mutated`, `operations`, `validation_results`, `evidence_paths`, `review_gate`, `capability_label`. | JSON parse, mutation-state checks, target-class checks. | Report example, validation results. | `needs_review`. | Confusing dry-run with apply evidence, production readiness. |
| lifecycle evidence packet | Collects validation, boundary, schema, fixture, and review evidence. | `evidence_id`, `task_id`, `artifact_refs`, `validation_commands`, `boundary_confirmation`, `warnings`, `remaining_risks`, `review_gate`. | Evidence completeness check. | Task-local evidence files. | `needs_review`. | Source-of-truth replacement, review bypass. |
| rollback-compatible lifecycle record | Captures inverse-operation evidence and rollback prerequisites. | `schema_version`, `record_id`, `lifecycle_plan_id`, `lifecycle_phase`, `target_class`, `path`, `operation_type`, `ownership_type`, `preimage_hash`, `postimage_hash`, `inverse_operation`, `rollback_preconditions`, `rollback_stop_conditions`, `evidence_refs`, `review_gate`, `rollback_execution_implemented`. | JSON parse, rollback-not-execution check. | Rollback record example. | `needs_review`. | Rollback execution, deletion of unknown/manual content. |
| fixture repository specification | Defines fixture source, target, expected, reports, rollback, and evidence roots. | `fixture_id`, `fixture_root`, `source_pack_path`, `target_root_path`, `expected_state_path`, `reports_path`, `rollback_records_path`, `evidence_path`, `scenarios`. | Fixture shape existence checks in future materialization task. | Fixture spec example and plan. | `needs_review`. | Fixture apply execution. |
| fixture pack specification | Defines the source pack used by fixture plans. | `pack_id`, `manifest_ref`, `files`, `managed_sections`, `generated_files`, `hashes`, `capability_labels`. | Hash and schema checks. | Future fixture pack evidence. | `needs_review`. | Target install apply or release packaging. |
| fixture expected-state specification | Defines expected post-state for dry-run or future fixture apply verification. | `expected_state_id`, `scenario_id`, `expected_files`, `expected_reports`, `expected_rollback_records`, `target_files_mutated_expected`. | Path, hash, and mutation-state checks. | Future expected-state evidence. | `needs_review`. | Active repo or target repo mutation. |
| lifecycle validation result | Records schema, example, fixture, boundary, and capability validation. | `validation_id`, `task_id`, `commands`, `results`, `warnings`, `blocked_operations`, `capability_labels`, `evidence_refs`. | Command result inspection and JSON/YAML parsing. | Validation evidence. | `needs_review`. | Acceptance, production readiness, release readiness. |

## Schema Files Created

- `.aide/apply/lifecycle-manifest.schema.json`
- `.aide/apply/lifecycle-plan.schema.json`
- `.aide/apply/lifecycle-report.schema.json`
- `.aide/apply/lifecycle-rollback-record.schema.json`

These schemas are minimal contract records. They are not permission slips for active repo apply, target repo apply, install apply, upgrade apply, lifecycle repair apply, rollback execution, uninstall execution, branch/worktree mutation, release publication, GitHub mutation, provider/model calls, Gateway calls, network calls, broad active-repo apply, production-ready, or release-ready claims.
