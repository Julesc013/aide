# H2 next bounded source: exact private Python closure

Implement and test the Python image recipe after the current image-source review.
This proposal covers source and synthetic fixtures only. A separate finite effect
manifest must bind every actual file copy, generated archive, new owned object,
package grant, module observation and isolated launch before any such effect.
No new profile, shared installation/parent ACL, loopback exemption or credential
change belongs to this slice.

## Scope and APIs

Add core/runtime/continuous_worker/windows_pe.py and windows_python_image.py,
plus test_continuous_worker_windows_pe.py and test_continuous_worker_python_image.py
under .aide/scripts/tests. Extend windows_image.py and its direct tests only for
an explicit derived-byte source type required by generated ZIP/_pth files. Keep
v1 ordinary-file admission unchanged. A strict v2 tagged row distinguishes
source_file from generated_bytes; generated rows are limited to the recipe's
exact python314.zip and python314._pth names and immutable admitted digests.
Never pretend generated bytes have a real source-file identity. Reuse the same
relative journal/root/stream/seal/grant protocol and independent bounds.

read_pe(data) returns immutable AMD64 import/delay-import/forwarder metadata;
validate_python_recipe() binds exact executable/private DLL metadata and the
named system contract; build_stdlib() deterministically derives archive bytes,
member custody and the fixed _pth payload from admitted file bytes. No parser or
builder loads inspected DLLs, imports inspected Python, consults PATH, follows
filters, fetches packages, or chooses an ambient runtime.

## Parser and bundle bounds

For this Python-only parser admit at most 16 MiB per PE, 96 sections, 16 data
directories, 2,048 import/delay records, 16,384 export slots, 260-byte ASCII DLL
names, 64 closure modules and 256 MiB total inspected bytes. Refuse overflow,
truncation, ambiguous section/raw overlaps, unsupported machine/optional header,
missing terminators, names outside mapped file bytes, malformed delay attributes,
escaping imports, case duplicates and unresolved forwarders. These are parser
limits, not a change to image/worker/H1 limits. The 359 MiB Codex image needs a
separately bounded reader before reusing this parser; do not read it whole here.

Admit at most 1,024 selected .py members, 2 MiB/member and 16 MiB total source,
with a derived archive ceiling of 18 MiB. The existing read-only inventory found
721 .py files / 12,544,530 bytes under Lib excluding site-packages and bytecode;
actual membership and every SHA must be frozen before building real inputs.
Use ZIP_STORED so bootstrapping encodings does not need zlib.pyd, sorted literal
member names, fixed DOS epoch timestamps, fixed file attributes, no comments,
extras, directory records, ZIP64, symlinks, .pth, .pyc or site-packages. Bind each
original member and the complete derived archive bytes. The _pth payload is
exactly python314.zip then . on separate LF lines, without import site.

## Bootstrap and meaningful tests

The first isolated command will use -I -S -B and a fixed trusted probe importing
encodings, json and os. Record actual sys.path/prefix/flags/module origins, prove
no site/user/custom environment path, and use JSON's pure-Python fallback if
_json.pyd is absent. Include codec bootstrap and indirect imports in fixtures;
source compilation alone does not prove this startup. Any unexpected extension,
DLL or path is a retained failure, not an expanded allowlist during the run.

Synthetic tests must cover malformed/truncated/overlapping PE structures,
unknown direct/delay/forwarded DLLs, missing exact system/API-set bindings,
wrong machine/hash, duplicate/escaping ZIP members, changed input bytes,
non-deterministic source order/mtime, missing encodings, injected site/.pth,
strict generated-byte kind/size/digest mismatch and failure before grant.
An actual later probe must bind private bytes and loaded modules, restricted
identity/Job, owned scratch writes and protected canary/controller denials.
AppContainer descendants, Python/Git/Codex worker use and model egress remain
separate cells. No actual copy/grant/launch or operational activation follows
from source-only passing tests.
