## Bounded Windows implementation slices

This remains admitted backlog; the decomposition does not activate a host or
change ACLs, credentials, firewall policy or accounts. The existing Job host
provides containment. Implement an actual security boundary before qualification.

1. H1 inventory and launcher: add a focused Windows security-capability module
   alongside the existing Job host. Inventory actual token, OS and supported
   AppContainer APIs. Prototype a marker-owned profile with a unique package
   SID and zero network capabilities; combine SECURITY_CAPABILITIES and JOB_LIST
   in the same suspended CreateProcess boundary. Read the created child's
   TokenIsAppContainer, package SID, capabilities, integrity and owned Job before
   resume; wrong or missing identity refuses without executing child code.
2. H2 owned filesystem: grant that package only read/execute on a pinned private
   runtime/tool image and the necessary access on the exact disposable worker
   clone/temp/output roots. Keep controller, broker, source pins, policy, capsules
   and credentials outside those grants. Capture object identities, actual DACLs
   and mandatory labels. Never modify shared Python/Git installation ACLs or
   equate a path/hash observation with ownership. Retain uncertain artifacts.
3. H3 real denial tests: the same token must successfully edit its clone but
   fail to read protected synthetic credential canaries, write broker/evidence
   children, alter protected DACLs, open the controller for process mutation,
   escape through substituted junctions or use a pre-existing loopback exemption.
   Test real descendants and supervisor death at all atomic launch boundaries.
   Use disposable owned canaries; never inspect actual secret values.
4. H4 controlled model egress: zero-network execution is not a complete Codex
   worker. Implement the existing AIDE provider/gateway boundary's narrowly
   authenticated task channel and prove direct credential/provider access is
   denied. The worker must receive no controller credential. If a loopback
   adapter is necessary, qualify explicit per-profile/per-endpoint filtering
   and refusal probes; do not grant general Internet access as a shortcut.
5. H5 acceptance: publish a source/OS/token/SID/root-object/DACL/network-policy
   receipt generated by the protected host observer. Test missing/stale/drifted
   receipts and access changes during execution. Replace the broker/issuer
   permissive fixture qualifier with this implementation, then run the actual
   registered tool and provider flows on the identified disposable host.

H1-H3 can be built before GitHub target setup. H4 and H5 must complete before
AIDE-CW-LIVE-PILOT-01. A missing AppContainer facility must yield a concrete
restricted-identity/VM alternative and new exact test plan, not a success flag.
Microsoft documents the dual user/package access check and capability-based
network boundary; actual qualification still requires these local probes.
