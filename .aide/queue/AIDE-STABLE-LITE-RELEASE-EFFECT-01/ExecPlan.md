# ExecPlan: AIDE Lite stable release effect

## Objective and source

Parent `AIDE-CONVERGENCE-AND-DELIVERY-01` remains active. The predecessor
WorkUnit independently accepted local preview at `4dcd896b`, tree `b8ae4507`,
with notes; its ZIP/tar are explicitly `preview_only` and `no_publish`.
Build a **distinct** final stable subject. This plan does not make old preview
bytes publishable or authorize an unreviewed effect.

## Scope and constraints

Only `task.yaml` allowed paths may change. Reuse the primary checkout and
owner-selected D scratch/retained/control roots; one intensive job at a time,
no extra physical worktree or new pool. Preserve the accepted generator and
canonical pack content. The source tree, release assets and effect manifest
must be exact, independently reviewed and rechecked immediately before effect.

## Milestones

1. Read current remote tags/releases and version policy. Classify installed
   `validate` and context warnings against the exact Windows Lite CLI profile;
   define offline and predecessor promises with evidence, support tier and
   environment. Select SemVer only in a frozen manifest.
2. Rebuild current export/release outputs under the D runner and prove
   post-commit zero-change replay. Add the smallest deterministic non-preview
   stable manifest/asset path where AIDE lacks one; test it with tiny fixtures,
   review changed source, and do not edit Q47/Q48 preview flags.
3. Qualify exact stable asset bytes in fresh and Git brownfield disposable
   consumers across supported install, customization, update, conflict,
   repair, rollback, interruption, detach and declared offline behavior.
   Reuse prior evidence only with valid source/dependency/oracle bindings.
4. Freeze source/tree, version/tag, assets/hashes, predecessor matrix,
   environment, effect commands and recovery plan. Obtain independent
   technical **ACCEPT** for that exact subject and effect; repair and rereview
   any changed subject.
5. Recheck actual refs and credentials in the real user context. Promote exact
   qualified source to main through the normal permitted route, create an
   immutable tag, publish assets, observe remote identities, download assets,
   verify hashes and run consumer acquisition/update from those downloads.

## Validation and evidence

Use AIDE `job` admission/collection, release bundle/validate/draft commands,
canonical checks, deterministic hash/ZIP inspection and final consumer oracles.
Record D job manifests, commands, resource peaks, logs, exit codes, scratch
retirement, exact source and asset digests in task evidence. Keep retained
warnings/skips visible. A source test or upload acknowledgement is not release
acceptance.

## Recovery

Before any irreversible effect, verify exact remote ref/tag and asset state.
On an ambiguous push/upload, observe remote state before retry. Never force
push, retag or silently replace published bytes. If a real external gate stops
one stream, preserve the exact candidate and continue independent permitted
work. The parent goal remains active until wider mandatory work is fulfilled.
