# Workbench Non-Authority Law

Workbench:

- binds registered views/actions;
- captures native context;
- projects native selection/workspace state;
- presents preview and evidence;
- supports approval interaction;
- requests apply through owning domain/host surfaces.

Workbench must not:

- call private tools directly;
- become product truth;
- bypass command/refusal/evidence contracts;
- own scheduler authority;
- own provider credentials;
- mutate repositories silently;
- own AIDE protocol authority.

This preserves live Dominium Workbench doctrine while allowing future read-only AIDE projections.

Workbench is not an authority source for product truth, protocol truth, scheduler authority, provider credentials, or repository mutation. Its operator interaction role is presentation, approval, and inspection.
